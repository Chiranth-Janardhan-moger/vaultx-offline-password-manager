Built Without Compromise

Most password managers rely on remote cloud storage that creates centralized targets for data breaches. VaultX is architected around absolute local device ownership.

Pure Offline Operation

The Android manifest contains zero internet permissions. VaultX cannot make outbound network requests, report telemetry, or transmit credentials.

Built-In 2FA Authenticator

Generate rotating six-digit one-time codes adhering to RFC 6238 without separate apps. Includes 30-second countdown rings and auto-clearing clipboard copies.

Digital Card Wallet

Store payment cards and banking records in visual containers. Features formatted card grouping and on-demand CVV reveal toggles.

Hardware Biometric Authentication

Authenticate directly using Android BiometricPrompt with KeyStore hardware isolation, protected against brute-force attacks via persistent lockout rate-limiting.

AES-256 Encryption

Vault payloads are encrypted with AES-256-CBC. Master keys are derived via PBKDF2 with 16-byte random salts generated through Java SecureRandom.

Fail-Closed Screen Security

Active Android window protection blocks screenshots and obscures credential previews in the recent applications view, failing closed on startup.

Auto-Clearing Clipboard

Copied credentials and TOTP codes are automatically wiped from the system clipboard after a configured timer (45 seconds default) to prevent clipboard snooping.

Tamper-Proof Backups

Export encrypted JSON backups protected by your custom passphrase. Integrates SHA-256 HMAC integrity signatures to reject altered files immediately.

Cryptographic Threat Model

Every architectural tier in VaultX enforces deterministic cryptographic boundaries on device.

Tier 1

Hardware Isolation

Android KeyStore protects vault wrapping keys in hardware TEE and StrongBox registers, requiring biometric user confirmation.

KeyStore + BiometricPrompt
Tier 2

Key Derivation

Master passwords derive AES keys using PBKDF2 with 16-byte random salts generated via Java SecureRandom.

PBKDF2-HMAC-SHA256 (16B Salt)
Tier 3

Payload Encryption

All password items, custom fields, bank cards, and 2FA secrets are serialized and stored under AES-256-CBC.

AES-256-CBC + PKCS7 Padding
Tier 4

Integrity Verification

Encrypted backup containers append cryptographic HMAC digests. Any byte tampering causes immediate decryption failure.

SHA-256 HMAC Container Verification
Tier 5

Display Guard

Operating system windows enforce fail-closed FLAG_SECURE to prevent screen scraping, screenshots, and recents leakage.

WindowManager.LayoutParams.FLAG_SECURE
Tier 6

Memory Sanitization

Master password char arrays are zero-wiped immediately following key derivation to prevent heap retention.

JVM CharArray Zero Wipe

Frequently Asked Questions

Details on VaultX’s security model, offline workflows, and data protection.

VaultX features an encrypted backup export system in Settings. You can create a password-encrypted JSON file derived with PBKDF2 and authenticated via SHA-256 HMAC. You can securely transfer this file to your other devices using private local solutions like Syncthing, local USB, SD card, or KDE Connect.
Because VaultX operates under a zero-knowledge architecture, no remote administrator can reset your credentials. However, during initial setup, VaultX provides optional local security questions which wrap a secondary recovery key. If you forget your password, you can answer your recovery questions to regain access.
